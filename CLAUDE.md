# CLAUDE.md

Personal homepage styled as a Unix man page. Static HTML, CSS and one script;
the only generated file is the Catppuccin palette.

## Layout

```
public/                     the deployable surface -- nothing outside it ships
  index.html                the man page
  css/palette.css           GENERATED -- do not edit
  css/style.css             fonts, layout, status bar
  js/man-page.js            status bar + key bindings
  assets/fonts/             Roboto Mono, self-hosted woff2 subsets
templates/palette.css.tera  whiskers template, writes into public/css/
```

Anything outside `public/` -- the template, `shell.nix`, the justfile, this
file -- is project tooling and is not part of the published site.

## Commands

`shell.nix` provides `catppuccin-whiskers`, `just` and `python3`; direnv loads
it via `.envrc`, otherwise run `nix-shell`.

```sh
just dev      # serve public/ at localhost:8000
just build    # regenerate public/css/palette.css from the template
just check    # fail if the committed CSS no longer matches the template
```

## Palette

`public/css/palette.css` is generated by [whiskers](https://whiskers.catppuccin.com)
from `templates/palette.css.tera` and committed. **Never edit the CSS** -- the
next `just build` discards the change and `just check` fails in the meantime.

To add or remove a color, edit the `colors` list in the template's frontmatter
and run `just build`. The page currently uses 13 of the 26 palette colors,
emitted as one `:root[data-flavor="..."]` block per flavor.

### `--check` requires an explicit path

All four flavors render into a *single* file, which whiskers treats as
single-output mode. In that mode `--check` takes the output path as an
argument:

```sh
whiskers templates/palette.css.tera --check public/css/palette.css
```

Omitting it fails with `--check requires a file argument in single-output
mode`. The whiskers docs say the path is unnecessary in multi-flavor mode, but
that applies to multi-*file* output, not this case.

## The page

`public/index.html` is hand-written and holds the content directly -- there is
no templating or build step for it. Sections follow man conventions: NAME,
SYNOPSIS, DESCRIPTION, OPTIONS, ENVIRONMENT, EXAMPLES, BUGS, AUTHORS, SEE ALSO.
Term/definition sections use `<dl>`.

The footer date is a literal string in the markup.

`public/js/man-page.js` provides a `less`-style status bar and the bindings
`j`, `k`, `gg`, `G`, `t` (cycle flavor), `y` (copy email), `e` (open email).
Without JavaScript the man page itself renders completely; the status bar is
empty markup that the script fills in, so it stays blank, and the bindings do
nothing.

Theme: an inline script in `<head>` sets `data-flavor` before first paint to
avoid a flash. It honours `prefers-color-scheme` until the visitor presses `t`,
after which the choice persists in `localStorage` under `catppuccin-flavor`.

## Conventions

- Two-space indent in HTML and CSS; the existing files are the reference.
- No frameworks, no bundler, no runtime dependencies. Keep it that way unless
  there is a reason not to.
- Fonts are self-hosted subsets; the page makes no external requests.
